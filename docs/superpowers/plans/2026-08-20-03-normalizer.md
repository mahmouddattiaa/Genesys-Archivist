# Genesys Archivist — Plan 3: Normalizer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a Genesys Architect flow configuration into a validated `FlowSnapshot` — nodes, edges, variables, dependencies, evidence — tested against a sanitized fixture derived from a real 47-node production flow.

**Architecture:** Pure transformation. `packages/normalization` takes the raw configuration object and returns a `FlowSnapshot`. No network, no filesystem, no Genesys SDK types. Every test runs offline against `fixtures/flow-config/inboundcall-47-nodes.json`, whose structure is byte-for-byte faithful to the real flow.

**Tech Stack:** TypeScript 5.6 strict, Vitest, Zod for boundary validation, Ajv for schema conformance.

**Spec:** [docs/superpowers/specs/2026-08-20-genesys-archivist-design.md](../specs/2026-08-20-genesys-archivist-design.md) §6.1

**Evidence base:** [S1](../../spikes/S1-source-path.md) and [S3](../../spikes/S3-references.md). Every structural claim below was measured against the live sandbox, not assumed.

## Global Constraints

- TypeScript strict, plus `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`.
- `packages/normalization` may import `@genesys-archivist/domain` and `@genesys-archivist/security` only. No SDK types cross its boundary.
- **Runtime validation at the boundary.** The configuration object is external input; validate before trusting any field.
- **Never silently drop a node.** An unrecognised `__type` becomes a node with `supportLevel: 'unsupported'` and an evidence pointer. A test asserts this.
- **Never invent a node.** Architect reuses action names as settings keys — `settingsActionDefaults.callData` is a defaults block, not a `DataAction`. Walk by structural position, never by key name. This mistake was made once already, in the S1 comparison harness.
- No `console.*`. Run `npm run verify` before every commit.
- **Toolchain notes for implementers.** Non-null assertions (`x[0]!`) are a lint error in `src/` though permitted in tests — destructure or guard instead. The installed zod is **version 4**: `.passthrough()` and `z.string().datetime()` are deprecated in favour of `.loose()` and `z.iso.datetime()`, and `@typescript-eslint/no-deprecated` fails the build on either.

## What the configuration actually looks like

Measured, not assumed. All of this is present in the fixture.

```text
config
  name, description, type, defaultLanguage, supportedLanguages
  nextTrackingNumber                 monotonic allocator; exceeds every assigned id
  variables[]                        flow-scoped
  flowSequenceItemList[]             10 items: 7 Task + 3 Menu
    ├ trackingId  (number)           unique across the flow, range 10..56
    ├ id          (GUID)             second identity
    ├ name, __type, startAction
    ├ variables[]                    task-scoped
    ├ actionList[]                   25 actions across all tasks
    └ menuChoiceList[]               12 choices across all menus, each with .action
  manifest                           resource references WITH stable ids (S3)
```

**Value wrapper.** Every settable value is `{ config: { <discriminator>: … }, text, type, … }` where the discriminator is one of `lit`, `emp`, `ref`, or an operator name.

**Expressions are ASTs, not strings:**

```json
"expression": { "config": { "==": { "operands": [
  { "GetAt": { "operands": [
      { "ref": { "type": "str_coll", "val": "2612d440-…" } },
      { "lit": { "type": "int", "text": "0" } } ] } },
  { "lit": { "type": "str", "text": "…" } } ] } } }
```

`ref.val` is the **variable's GUID**, so variable read indexing is exact rather than textual.

```ts
// packages/domain/src/value-ref.ts
export type ValueRef =
  | { readonly kind: 'literal'; readonly dataType: string; readonly text: string }
  | { readonly kind: 'unset' }
  | { readonly kind: 'variableRef'; readonly variableId: string; readonly dataType: string }
  | {
      readonly kind: 'expression';
      readonly operator: string;
      readonly operands: readonly ValueRef[];
    }
  | { readonly kind: 'opaque'; readonly discriminator: string };

const isRecord = (v: unknown): v is Record<string, unknown> =>
  typeof v === 'object' && v !== null && !Array.isArray(v);

const str = (v: unknown): string => (typeof v === 'string' ? v : '');

/**
 * Architect wraps every settable value. A top-level value carries a `config`
 * object; operands nested inside an expression do not, so both shapes are
 * accepted. The single key inside is the discriminator.
 */
export function parseValueRef(raw: unknown): ValueRef {
  if (!isRecord(raw)) return { kind: 'unset' };
  const inner = isRecord(raw['config']) ? raw['config'] : raw;

  // Destructure rather than index-and-assert: `keys[0]!` trips
  // no-non-null-assertion, which is an error in src/ though allowed in tests.
  const [discriminator] = Object.keys(inner);
  if (discriminator === undefined) return { kind: 'unset' };
  const body = inner[discriminator];

  if (discriminator === 'emp') return { kind: 'unset' };

  if (discriminator === 'lit' && isRecord(body)) {
    return { kind: 'literal', dataType: str(body['type']), text: str(body['text']) };
  }

  if (discriminator === 'ref' && isRecord(body)) {
    return { kind: 'variableRef', variableId: str(body['val']), dataType: str(body['type']) };
  }

  if (isRecord(body) && Array.isArray(body['operands'])) {
    return {
      kind: 'expression',
      operator: discriminator,
      operands: body['operands'].map(parseValueRef),
    };
  }

  // Unknown constructs are preserved as opaque rather than dropped.
  return { kind: 'opaque', discriminator };
}

/** Every variable id read anywhere inside a value, including nested operands. */
export function collectVariableReads(value: ValueRef, into: Set<string> = new Set()): Set<string> {
  if (value.kind === 'variableRef') into.add(value.variableId);
  if (value.kind === 'expression') for (const o of value.operands) collectVariableReads(o, into);
  return into;
}
```

### Task 4: Variable extraction and the read/write index

**Files:**

**Interfaces:**

- Produces: `extractVariables(cfg): readonly ExtractedVariable[]` and `indexVariableUsage(cfg, nodes): VariableUsageIndex` mapping variable ID → `{ readBy: NodeId[]; writtenBy: NodeId[] }`.

**Why this task is the payoff.** Because `ref.val` carries the variable's GUID, usage indexing is exact. ## Parallel execution

Partition by file, and respect the real dependency order.

```text
WAVE A   Task 1  packages/domain      ValueRef
         Task 2  packages/normalization  config-schema  (independent of Task 1)

WAVE B   Task 3  extract-nodes        needs 2
         Task 5  extract-dependencies needs 2 only — can run beside 3

WAVE C   Task 4  extract-variables    needs 1 and 3
         Task 6  extract-edges        needs 3

WAVE D   Task 7  evidence             needs 3, 4, 5
         Task 8  normalize            needs everything
```

One agent owns `packages/normalization/src/index.ts` per wave.

## What this plan leaves out

Graph analysis — reachability, cycles, caller journeys, dead-branch findings — is `packages/analysis` and comes next. The normalizer's job is a faithful `FlowSnapshot`; drawing conclusions from it is a separate concern with separate tests.
